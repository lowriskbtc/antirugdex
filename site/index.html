The ARD fee token

A 0.25% Token-2022 transfer fee funds the build. Three authorities are permanently revoked at launch, which is what separates a locked fee from a promise:

Mint authority — revoked

The supply is fixed. No one can print more, including us.

Freeze authority — never set

No account can be frozen. Your tokens cannot be immobilised.

Fee authority — revoked

The 0.25% is locked forever. Nobody can raise it toward 100% and turn the token into a honeypot — the usual failure mode for a taxed token.

One authority stays live by design: withdrawWithheldAuthority, which collects fees already withheld by the 0.25%. It cannot touch anyone's principal, mint supply, or change the rate. Revoking it would make the fee uncollectable, not safer.

Open the launcher → devnet

Create a Token-2022 mint from your browser — supply fixed and mint authority revoked in one transaction, freeze authority never set. It runs the same instruction builder the command-line tool uses, and refuses to build against any chain but devnet, checked by genesis hash rather than by a setting.

Open the grader →

Paste any Solana mint — ours or anyone else's — and read what is actually deployed: authorities, fee config and cap, the extensions most checklists skip, and holder concentration. It runs in your browser against the chain, with no third-party API and no pass/fail badge. Checks that could not run are flagged, never hidden.

Or check it in one command — no need to take our word for anything:

spl-token display <MINT_ADDRESS>

Look for Mint authority: (not set), Freeze authority: (not set), and a transfer fee config whose config authority is unset.
